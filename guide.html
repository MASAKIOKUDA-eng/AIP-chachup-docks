3. 判断表（どれを選ぶか）

推論の方式

方式向いている状況注意点
オンデマンド変動する負荷、試行段階アカウントのクォータを超えると 429（スロットリング）
クロスリージョン推論急なトラフィック、スループット確保推論プロファイルの地理的範囲がデータ所在の要件に合うか
バッチ推論即時性が不要な大量処理入力は S3 の JSONL。最小レコード数のクォータあり
Provisioned Throughput安定した大量負荷、一部のカスタムモデル確保している間は使わなくても課金
プロンプトキャッシュ長い共通プレフィックスを繰り返し送るモデルごとの最小トークン数と TTL。書き込みは割高な場合あり
インテリジェントプロンプトルーティング同じモデルファミリー内で、質問ごとに安いモデルと高性能なモデルを使い分けたい対応モデルが限られる
SageMaker AI エンドポイント独自モデルや Bedrock にないオープンモデルを、インスタンスやコンテナを制御して動かしたいインフラの選定と運用が必要

モデルの改善手段（コストと手間の小さい順）

手段使う場面
プロンプトエンジニアリング / Prompt Management出力形式や口調の調整。まず最初に試す
RAG（Knowledge Bases）社内の最新情報や根拠に基づいた回答が必要
モデル蒸留（Distillation）大きなモデルの品質を、小さく速く安いモデルに移したい
ファインチューニングラベル付きの例で特定タスクの振る舞いや形式を学習させたい
継続事前学習ラベルなしの大量の専門分野のテキストで知識を広げたい

エージェントの基盤

選択肢向いている状況
Bedrock Agentsコンソールや API の設定中心で、アクション グループ（Lambda / OpenAPI）とナレッジベースを組み合わせて素早く作る
Bedrock AgentCoreLangGraph、CrewAI、Strands Agents など任意のフレームワークやモデルで作ったエージェントを、セッション分離・長時間実行・MCP ツール・ID 管理つきで本番運用する
Bedrock Flows手順が決まった処理（プロンプト、ナレッジベース、Lambda、条件分岐）をつなぐ。エージェントほどの自律性は不要
Step Functions再試行、並列処理、人による承認、他の AWS サービスとの連携を含む業務ワークフロー

ベクトルストア

選択肢向いている状況
OpenSearch ServerlessKnowledge Bases のクイック作成で使える。容量管理なしでベクトル検索とキーワード検索（ハイブリッド）
OpenSearch Service（マネージドクラスター）既存のクラスターを活用したい、細かくチューニングしたい
Aurora PostgreSQL（pgvector）既存のリレーショナルデータと一緒に管理したい、SQL で結合したい
Neptune Analyticsエンティティ間の関係をたどる GraphRAG
S3 Vectors大量のベクトルを低コストで保存したい（遅延の要件が緩い）
MemoryDB / ElastiCache非常に低いレイテンシ、セマンティックキャッシュ

4. 機械学習

Amazon Bedrock（推論 API）

役割
複数のプロバイダーの基盤モデルを、サーバーレスに単一の API で使えるサービス。
使いどころ
Converse / ConverseStream はモデル間で共通の形式（ツール使用、マルチターン、ストリーミング）。InvokeModel はモデル固有の形式。
着眼点
推論方式の選択（オンデマンド / バッチ / クロスリージョン / Provisioned Throughput）、プロンプトキャッシュ、429 の対策（ジッター付き指数バックオフ）、モデル呼び出しログ、コンテキストウィンドウ超過の対処。
組み合わせ
Lambda、API Gateway、Step Functions、CloudWatch、PrivateLink
資料
Converse API / バッチ推論 / クロスリージョン推論 / プロンプトキャッシュ

Amazon Bedrock Knowledge Bases

役割
RAG のための取り込み（解析・チャンキング・埋め込み・格納）と検索をまとめて行うマネージド機能。
使いどころ
Retrieve（検索結果だけ）と RetrieveAndGenerate（回答生成まで）。S3、Web クローラー、Confluence、SharePoint、Salesforce などのデータソースに対応。構造化データ（Redshift など）への自然言語クエリも可能。
着眼点
チャンキング（固定 / 階層 / セマンティック / なし）、解析（既定 / 基盤モデル / Bedrock Data Automation）、メタデータフィルタ（.metadata.json）、増分同期、リランクモデル、ハイブリッド検索。
組み合わせ
S3、OpenSearch Serverless、Aurora、Neptune、Bedrock Agents、Guardrails
資料
チャンキング / メタデータ / 同期

Amazon Bedrock Agents

役割
基盤モデルが計画を立て、アクション グループ（Lambda、OpenAPI スキーマ）やナレッジベースを使ってタスクを実行するマネージドなエージェント。
使いどころ
問い合わせ対応、予約や照会などの業務 API の呼び出し。マルチエージェントの連携（スーパーバイザー）。
着眼点
ユーザー確認（requireConfirmation）、Return of Control（アプリ側でアクションを実行）、トレースによるデバッグ、セッション属性、エイリアスとバージョン。
組み合わせ
Lambda、Knowledge Bases、Guardrails、DynamoDB
資料
仕組み / ユーザー確認

Amazon Bedrock AgentCore

役割
任意のフレームワークとモデルで作ったエージェントを、安全かつ大規模に本番運用するためのサービス群。
使いどころ
Runtime：セッション分離されたサーバーレスのホスティング（既定で最大 8 時間）。Gateway：API・Lambda・既存サービスを MCP 対応ツールに変換。Identity：エージェント用の ID と外部サービスの資格情報（OAuth など）の管理。Memory：短期・長期の記憶。Code Interpreter / Browser：コード実行とブラウザ操作。Observability：トレースとメトリクス。
着眼点
既存のエージェントのコードを活かしたまま運用基盤を用意する場面。Lambda の 15 分制限を超える長時間処理。利用者の代わりに外部 SaaS にアクセスする委任。
組み合わせ
Cognito（受信認証）、Lambda、CloudWatch、VPC
資料
AgentCore とは / クォータ

Amazon Bedrock Guardrails

役割
入力と出力に安全対策を適用する機能。
使いどころ
コンテンツフィルタ（有害カテゴリ、プロンプト攻撃）、拒否トピック、単語フィルタ、機密情報フィルタ（PII のブロック / マスク、正規表現）、コンテキストグラウンディングチェック（ハルシネーション検出）、自動推論チェック。
着眼点
ApplyGuardrail API でモデルを呼ばずに評価でき、SageMaker や外部のモデルにも使える。Agents や Knowledge Bases にも関連付けられる。
組み合わせ
Bedrock の推論 API、Agents、Knowledge Bases、SageMaker AI、CloudWatch
資料
概要 / ApplyGuardrail

Amazon Bedrock Prompt Management / Flows

役割
Prompt Management はプロンプトを変数つきのテンプレートとして保存し、バージョン管理する機能。Flows はプロンプト、ナレッジベース、Lambda、条件分岐などのノードをつないだワークフローを作る機能。
着眼点
プロンプトのガバナンス（承認されたバージョンだけを本番で使う、変更履歴を残す）。決まった手順の処理を、コードを書かずに組み立てる。
資料
Prompt Management / Flows

Amazon Bedrock Evaluations / モデルのカスタマイズ

役割
モデルや RAG の評価（自動評価、LLM-as-a-judge、人による評価）と、ファインチューニング、継続事前学習、蒸留によるカスタマイズ。
着眼点
RAG 評価は「検索のみ」（ContextRelevance、ContextCoverage）と「検索と生成」（Correctness、Faithfulness など）に分かれる。評価を CI/CD の品質ゲートに組み込む。
資料
RAG 評価のメトリクス / モデルのカスタマイズ

Amazon SageMaker AI（Clarify、Model Monitor、Ground Truth を含む）

役割
モデルの構築・学習・デプロイの基盤。JumpStart でオープンモデルをデプロイ。Clarify はバイアスと説明性、Model Monitor は本番のデータやモデル品質の変化の監視、Ground Truth はラベル付けと人によるフィードバックの収集。
着眼点
Bedrock にないモデルや独自のコンテナを使う、インスタンスの種類を指定したい、といった要件では SageMaker AI のエンドポイント。Guardrails は ApplyGuardrail で併用できる。
資料
SageMaker AI / Bedrock と SageMaker AI の選択

Amazon Q Business / Amazon Q Developer / Amazon Quick

役割
Q Business は社内データに接続して使える生成 AI アシスタント（データソースのアクセス権限を反映）。Q Developer はコード生成やレビュー、AWS の操作を支援。Amazon Quick は BI と生成 AI を組み合わせた業務向けのサービス。
着眼点
「独自のアプリを作るか、マネージドなアシスタントで足りるか」の判断。開発をほとんどせずに社内 Q&A を実現したい場合は Q Business が候補。
資料
Q Business / Q Developer

AI サービス（Textract / Transcribe / Comprehend / Kendra / Lex / Rekognition / A2I）

役割
Textract：文書からテキスト・表・フォームを抽出。Transcribe：音声の文字起こし。Comprehend：エンティティ、PII、感情の検出。Kendra：企業向けの検索（RAG の検索器にもなる）。Lex：チャットボットの会話インターフェイス。Rekognition：画像・動画の分析。Amazon Augmented AI（A2I）：人によるレビューのワークフロー。
着眼点
生成 AI の前処理（文字起こし → 要約、OCR → 抽出）や、信頼度が低い結果だけを人が確認する構成。Comprehend の PII 検出は取り込み前のデータのマスキングに使える。
資料
Textract / Comprehend PII / A2I

5. 分析・データベース・ストレージ

Amazon OpenSearch Service / OpenSearch Serverless

役割
ベクトル検索（k-NN）とキーワード検索を備えた検索エンジン。Knowledge Bases のベクトルストアの代表。
着眼点
ハイブリッド検索、メタデータのフィールドはキーワード型で定義、インデックスの設定（次元数は埋め込みモデルに合わせる）。Neural プラグインで Bedrock の埋め込みモデルと連携できる。
資料
Serverless のベクトル検索

Amazon Aurora / RDS / DynamoDB / ElastiCache / Neptune / DocumentDB

役割と使いどころ
Aurora PostgreSQL：pgvector でベクトルを業務データと一緒に管理。DynamoDB：会話履歴、セッション状態、エージェントのツールの業務データ（TTL で期限切れを自動削除、Streams で変更を連携）。ElastiCache：応答キャッシュやセマンティックキャッシュ。Neptune：ナレッジグラフと GraphRAG。DocumentDB：JSON 文書とベクトル検索。
着眼点
既存データの場所と、必要なレイテンシ・クエリの種類から選ぶ。
資料
Aurora をベクトル DB として使う / DynamoDB TTL

AWS Glue / Amazon Athena / Amazon Kinesis / Amazon MSK / Amazon EMR / Amazon QuickSight

役割と使いどころ
Glue：取り込み前のデータの変換・品質チェック（Data Quality）とカタログ。Athena：S3 上のデータへの SQL（呼び出しログの分析など）。Kinesis / MSK：ストリーミングデータの取り込み（リアルタイムに要約・分類）。EMR：大規模な前処理。QuickSight：利用状況やコストの可視化。
着眼点
RAG に入れる前のデータ検証パイプライン（試験ガイド タスク 1.3）。
資料
Glue Data Quality

Amazon S3 / EBS / EFS

役割と使いどころ
S3：RAG のソース文書、バッチ推論の入出力、学習データ、ログの保存。Intelligent-Tiering やライフサイクルでコストを最適化、クロスリージョンレプリケーションで DR。EFS / EBS：コンテナや EC2 で動くモデルのファイル。
資料
S3 ライフサイクル

6. コンピューティング・コンテナ

AWS Lambda / Amazon ECS / Amazon EKS / AWS Fargate / Amazon EC2 / AWS App Runner

役割と使いどころ
Lambda：Bedrock 呼び出しやエージェントのツールの実装（最大 15 分）。ECS / EKS / Fargate：長時間の処理や独自のサービス、セルフホストのモデル。EC2：GPU インスタンスでのモデル実行。App Runner：コンテナの Web アプリを簡単に公開。
着眼点
実行時間（15 分を超えるか）、同時実行数とモデルのクォータのバランス（同時実行数を増やすとスロットリングが悪化しうる）、レスポンスストリーミング。
資料
Lambda のクォータ

7. アプリケーション統合・API

AWS Step Functions

役割
複数のステップからなる処理を、再試行やエラー処理、並列処理つきで実行するワークフロー。Bedrock との最適化された統合がある。
着眼点
人による承認は .waitForTaskToken（Standard ワークフローのみ。Express はリクエスト・レスポンスのみ）。Map 状態で大量文書を並列処理。
資料
サービス統合のパターン / Bedrock との統合

Amazon EventBridge / Amazon SQS / Amazon SNS / Amazon AppFlow / AWS AppConfig

役割と使いどころ
EventBridge：S3 の更新などのイベントを受けて取り込みを開始、スケジュール実行。SQS：リクエストのバッファリングと平準化（スロットリング対策）、DLQ。SNS：通知とファンアウト。AppFlow：SaaS のデータを S3 へ取り込み。AppConfig：プロンプトやモデル ID、機能フラグの安全な切り替え。
着眼点
非同期化して疎結合にする。設定変更（モデルの切り替えなど）をデプロイなしで段階的に行う。
資料
SQS / AppConfig

Amazon API Gateway / AWS AppSync / Amazon CloudFront

役割と使いどころ
API Gateway：REST / HTTP / WebSocket API。使用量プランとスロットリングで利用者ごとに制限。AppSync：GraphQL とリアルタイムのサブスクリプション。CloudFront：フロントエンドの配信と WAF の適用。
着眼点
ストリーミング表示には WebSocket など双方向の通信路が必要。
資料
WebSocket API

Amazon Cognito / AWS WAF / Amazon Macie

使いどころ
Cognito：利用者の認証とトークン（テナント ID などの属性を検索フィルタに使う）。WAF：API への攻撃やレート制限。Macie：S3 に置いた学習データや RAG のソースに含まれる機密データの検出。
資料
Macie

AWS PrivateLink（インターフェイス VPC エンドポイント）

使いどころ
VPC から Bedrock（bedrock-runtime、bedrock-agent-runtime など）へインターネットを経由せずに接続。エンドポイントポリシーで許可する操作やモデルを制限。
資料
Bedrock のインターフェイス VPC エンドポイント

9. 管理とガバナンス（監視・コスト）

Amazon CloudWatch（Logs、Synthetics を含む）/ AWS X-Ray / Amazon Managed Grafana

使いどころ
Bedrock のメトリクス（Invocations、InvocationLatency、InvocationThrottles、InputTokenCount、OutputTokenCount など）、モデル呼び出しログ、ダッシュボードとアラーム。X-Ray で処理の遅い箇所を特定。Synthetics で定期的な動作確認。
着眼点
トークン数の監視によるコスト管理、レイテンシとエラー率のアラーム、ログからのプロンプトのトラブルシューティング（試験ガイド スキル 5.2.5）。
資料
bedrock-runtime のメトリクス / モデル呼び出しログ

AWS CloudTrail

使いどころ
API 操作の記録（誰が、いつ、どのモデルやエージェントを操作したか）。プロンプトと応答の本文は記録されないため、本文の監査はモデル呼び出しログを使う。
資料
Bedrock と CloudTrail

AWS Cost Explorer / Cost Anomaly Detection / Auto Scaling / Systems Manager / Service Catalog / Well-Architected Tool

使いどころ
コストの分析と異常検知（急なトークン消費の増加）、コスト配分タグ（アプリケーション推論プロファイルで用途別にコストを分ける）。SageMaker エンドポイントの Auto Scaling。Systems Manager Parameter Store で設定管理。Service Catalog で承認済みの構成を配布。Well-Architected Tool の Generative AI Lens でレビュー。
資料
Generative AI Lens / 推論プロファイル
